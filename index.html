页面分析工具对比

tChrome 当前 page.* 体系 vs 主流浏览器 Agent 做法。重点看：分层是否清晰、单次返回是否有界、引用是否可操作。

1. 四类主流路径

路径代表核心做法体积控制
可达性树 Playwright aria / browser-use role+name 稀疏树，只留可交互/语义节点；用 ref 或 role/name 操作 剪枝 + 选择器，不发全 DOM
SoM / 快照 WebVoyager、GUI Agent 截图或可见控件列表 + 编号；按编号点选 limit + truncated（常见 40/100）
区域阅读 多款浏览 Agent 区域目录 → 单区域正文 → 单元素详情 按需下钻，正文限长
多模态 computer-use viewport 截图 + 坐标；文字工具作补充 一屏一张图

2. 推荐分析链路（有界）

get_summary 标题 / url / regionCount / interactiveCount / headings 小
list_regions 区域 id、role、name、interactiveCount 小
list_interactive 可选 regionId + limit + total/truncated（可选 text 过滤） 应有界
inspect_region mode=text|elements|both + 长度上限 应有界
inspect_element 单节点：tag / name / rect / 状态 小
click / type 只用 list/inspect 返回的 id，不回读全页 小
主流共识：默认短返回；模型要「还有多少」时看 total/truncated，再决定是否继续 list 或 inspect 单点。

3. tChrome 现状对照

能力你已有主流习惯差距
页面概况 page.get_summary 摘要层 对齐
区域目录 page.list_regions 结构层 对齐
可交互枚举 page.list_interactive_elements（可 regionId） list + limit + truncated 无 limit / truncated / text
区域详情 page.inspect_region 限长 / mode region+elements+text 整包
单元素 page.inspect_element 单点字段 对齐
文本找控件 snapshot_page / find_on_page（limit 40–100） SoM / find + truncated 已分页 与 page.* 双体系
截图 capture_page viewport/full/element 多模态 对齐
操作目标 page.click(e_) vs click(el_) 单一 ref 体系更常见 双 ID，成本高
关键缺口：职责拆分已经够细，缺的是 单次返回有界。大 list / 大 region 直接进 <pageObservedHistory>.result，再被「最近 2 批压缩保护」冻在窗口里 → 200K 被反复顶穿。

4. 建议的 list / inspect 形态

page.list_interactive_elements(tabId, regionId?, limit=40, text?)
→ { ok, elements: [...], total, truncated }

page.inspect_region(tabId, id, mode=text|elements|both, limit?)
→ { ok, region, text?, elements?, total, truncated }

// 保持不变
page.get_summary(tabId)
page.inspect_element(tabId, id)
page.click(tabId, id)

和上下文策略的关系

  • 上游限流（工具默认短返回）— 每一刀都生效，优先做。
  • 观察滑动留存（最近 1 批全文，更早 cleared）— 兜底，防 JS/截图等其它大块。
  • Subagent — 适合整站长流程隔离，不是日常 list 问题的第一刀。

5. 实施优先级

优先级动作预期
P0 list_interactive_elements 增加 limit / total / truncated（可选 text） 直接砍掉最常见的大 result
P0 观察投影：最近 1 批全文，更早自动 {ok,cleared:true} 降低 200K 反复触发
P1 inspect_region mode + 限长 防止区域整包
P2 skill/提示词写死「summary → list(有界) → inspect 单点」 降低模型乱全页扫描
P2 评估 e_/el_ 是否收敛 减模型认知负担（改动大，可后置）
