# 宿主与浏览器协作

浏览器适合观察真实页面、登录态和交互；宿主适合文件处理、计算、本地进程和系统资源。遇到明确限制时切换能力，避免在同一个失败入口反复尝试。

## 根据缺口选择能力

- 页面脚本受 CSP 或跨域限制：在授权范围内，用宿主 local_run 执行计算或请求。宿主请求的 Cookie、代理、证书和网络环境可能与浏览器不同，不能直接把宿主成功当成页面成功。
- Canvas 或复杂组件没有完整 DOM：结合截图和页面探针读取状态；需要时检查 localStorage 或 IndexedDB 中相关数据。写入存储会改变应用状态，只在任务授权涵盖该操作时执行，并检查刷新后的实际行为。
- 网页内部录制用 video_record；需要标签栏、浏览器界面或其他应用时才使用系统录屏能力。
- 联调本地服务：先启动服务并确认就绪，再用 open_url 打开对应地址验证。需要接口证据时，按下方监听规则选择 network_grep / wait_response 或 page_submit_wait。

network_grep 和 wait_response 监听后续响应，不回查历史；已有响应直接使用原证据，按钮提交优先 page_submit_wait，避免先阻塞等待再触发请求。

动态工具按需 catalog_add，加载后依据 schema 调用。一次操作成功后进入下一项验证；已有结果按执行规则记入 workspace_write，缺原文再沿 callId 使用 evidence_search。

## 让反馈连接两个环境

1. 明确本次需要证明的结果，例如端口就绪、接口结构匹配或按钮操作成功。
2. 启动需要的进程，保存 processId 或自己创建的进程标识；通过就绪接口、日志或标志文件确认可用，不用固定等待时长猜测。
   local_run 心跳返回的 processId 用 local_process_status 查询、local_process_stop 停止；其他工具返回的 jobId 用 job_status / job_stop，不能混用两种编号。
3. 执行浏览器操作，检查页面和相关接口结果。失败时用这一轮的错误决定检查宿主进程还是页面状态，无需重新检查整个环境。
4. 对独立部分分别验证；宿主测试通过而浏览器失败时，调查两端差异，不把一个环境的结果代替另一个。

## 产物和进程

临时脚本、录屏和分析产物写入 <overview> 的服务数据目录或用户指定路径；仓库只存任务要求的源码和长期维护文件。

系统录屏按所用工具的正常停止方式结束；例如支持 SIGINT 的录制进程可用该信号完成文件收尾，不用 SIGKILL 强停。检查输出文件实际可读。

任务结束或失败后，停止本次创建且已不再需要的进程，保留用户需要继续使用的服务。清理仅针对自己的资源，不按进程名批量终止已有任务。
