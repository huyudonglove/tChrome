# 图形滑块验证

适用于页面上由图片图层、滑轨和手柄组成的验证码。根据当前页面证据选择自动求解、手动定位或请用户完成；不把某一种题型或轨迹当作所有站点的通用解法。已有当前题与可靠落点时直接操作，不为遵循流程重复探测。

## 识别本题与位移

- 先辨别题型：`solve_slider` 面向可唯一定位缺口的拼图；重复字符、图标或多个相似目标不能只凭第一次目测猜位移。自动工具返回 `requiresUser`、低置信或 `ambiguous-match` 时，停止盲拖，补充证据或交给用户。
- 可结合 `capture_page` 的局部截图与 `page_eval_expr` 读取图层、轨道和手柄的当前几何。透明窄前景可能与底图同高（例如 50×200 与 300×200），不能只筛大图或按高度排除；优先检查同一验证码容器内的图层及真正可拖动的手柄。
- 区分截图裁切坐标、设备像素和页面 CSS 坐标；计算前景当前位置到目标位置的相对位移，再从真实手柄中心换算拖动终点。截图或推算不明确时不要假定圆形标记就是缺口，也不要沿用上一题的数值。
- 拖动前若图片数据刷新、弹窗重新出现或关闭，重新确认当前题图与几何；回弹换题后旧图、旧坐标和旧元素引用失效。无需机械地重查无变化的整页。

## 拖动与反馈

`drag` 默认是较快的精确轨迹。用户希望更平缓时，可在当前已确认的题上显式使用 `humanize` 的 `overshoot`、`noise` 等选项，控制一次尝试并观察结果；这些选项同时改变步数、轨迹与时长，不能指定持续秒数。若要严格比较速度因素，应保持题图和落点等条件可比；一次较平缓轨迹通过不能证明“仅速度”起作用。

每次只按当前题的可靠落点尝试；出现回弹、换题或拒绝时先看实际反馈，必要时查看校验响应的业务字段，不连续复用旧落点。工具 `ok` 只说明拖动执行，HTTP 200、视觉对齐、手柄移动或弹窗暂时消失都不是独立的通过证据。自动求解的服务端状态不明确时按未确认处理，不把模糊响应当作成功。

## 按业务目标验收

例如发送邮箱验证码，应核对弹窗关闭、发送成功提示及倒计时，再检查邮箱确有本次新邮件；旧验证码不能代替新邮件。未通过则说明实际阻塞，不宣称验证码已经发送。动作后页面状态变化与接口结果相互矛盾时继续核对，不因单个信号草率结论。

验证码通过只完成当前验证步骤，不自动授权后续勾选协议、提交注册或其他业务动作；按用户对这些动作的明确授权继续。复用既有页面与工具记录，必要时用 `observation_write` 保存当前题和验收结论，避免在下次换题后使用过期证据。
