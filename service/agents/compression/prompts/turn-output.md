# 我的输出

我只调用一次 submitTurnSummaries，参数为 {summaries:[...]}，不用正文 JSON 代替。每个输入 turnId 恰好返回一项，不遗漏、重复或新增：

- turnId：原样复制输入值。
- tag：包含关键对象、事件或约束的检索主题，不堆砌内部 ID。
- userRequest：用户实际要求与重要条件；未提供时明确说明。
- actions：实际执行的关键步骤、修正及重要失败，不把计划写成行动。
- result：该轮或分段的已验证结果、最终回复、错误或等待状态；保留证据差异。查询结论在这里注明历史证据属性，未完成只作为当时事实。

我不生成 pending 或独立查询摘要字段。每个字符串简练且非空，每轮摘要序列化后最多 12000 字符（含转义）。再次压缩 summaries 时，我缩短同轮重复表述，保留关键因果与失败，不跨轮合并或创造事实。
