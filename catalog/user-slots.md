# User 插槽清单

本文件维护 user 插槽的功能与装配顺序。新增、删除、重命名或调整 user 插槽职责、顺序时，同步更新本文件、对应插槽文件、窗口模板和装配测试。

当前状态：已完成独立文件装配；实际顺序与下表一致。每槽文件位于 `catalog/slots/user/<name>.md`，包含用途、来源、边界与 `{{data}}` 数据占位；静态 system 规则无附加数据。

| 顺序 | 分组 | 插槽 | 功能 |
| --- | --- | --- | --- |
| 1 | 方法 | `#skill` | 提供已加载的网页操作方法与注意事项，帮助选择执行方式。 |
| 2 | 输入 | `#userInput` | 保存本轮用户原话，明确本轮请求。 |
| 3 | 输入 | `#userInputHistory` | 提供此前用户原话，用于理解指代、补充条件与方向变化。 |
| 4 | 目标 | `#goal` | 保存当前工作目标，供判断进展与完成情况。 |
| 5 | 目标 | `#goalHistory` | 保存被替换的旧目标，解释方向变化，不作为待执行清单。 |
| 6 | 页面 | `#currentTab` | 提供用户发话时的标签快照，确定任务起始页面。 |
| 7 | 页面 | `#currentPage` | 提供最近一次成功观察得到的页面信息，辅助判断操作对象与页面状态。 |
| 8 | 记忆 | `#projectMemory` | 提供项目背景、术语与长期约束；当前实现保存在本会话内。 |
| 9 | 记忆 | `#conversationMemory` | 提供本会话已确认的事实、偏好与决定。 |
| 10 | 记忆 | `#turnMemory` | 提供阶段进展、临时发现和待处理事项。 |
| 11 | 记忆 | `#contextSummary` | 汇总目标、已完成部分、阻碍与下一步，便于理解长任务整体状态。 |
| 12 | 记忆 | `#notes` | 保存按 key 修改的工作笔记，如清单、候选项和中间数据。 |
| 13 | 证据 | `#toolIO` | 提供实际工具调用、返回与错误，作为判断操作结果的依据。 |
| 14 | 证据 | `#observation` | 提供较早执行记录的摘要与回查标识，支持按需获取详细证据。 |
| 15 | 工具 | `#tools` | 提供当前已加载动态工具的用法，由统一工具目录生成。 |

## 管理边界

- 本清单负责导航和职责定义，窗口模板按清单顺序装配。
- 每个插槽的来源、用途和数据模板由其独立文件维护。
- `#tools` 是 user 内的说明槽；API 的 `tools[]` 承载可调用工具定义。
- system 插槽清单单独维护在 [system-slots.md](system-slots.md)。

维护要求：增删、重命名或调整职责与顺序时，同步修改本清单、独立槽文件、窗口模板、装配测试与 docs/examples 窗口快照。工具说明唯一来源是 `catalog/tools/*.json` 的 `function.description`；index 只做目录分类，不维护用途或参数手册。
